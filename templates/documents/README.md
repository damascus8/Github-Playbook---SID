# Document templates

Copy only the templates your project needs and move them into a location that fits its structure, for example `docs/` or `docs/adr/`.

| Template | Use it for |
|---|---|
| `PRD.template.md` | Product/feature brief and acceptance criteria |
| `ARCHITECTURE.template.md` | System components, data flow, operations, and decisions |
| `ADR.template.md` | One significant technical decision and its consequences |
| `API_SPEC_CHECKLIST.template.md` | Reviewing API contract completeness |
| `THREAT_MODEL.template.md` | Assets, trust boundaries, threats, controls, residual risk |
| `TEST_PLAN.template.md` | Scope, scenarios, test data, entry/exit criteria |
| `DEPLOYMENT_RUNBOOK.template.md` | Deploy, observe, diagnose, and operate a system |
| `ROLLBACK_PLAN.template.md` | Safe rollback and recovery procedure |
| `INCIDENT_POSTMORTEM.template.md` | Blameless incident review and corrective actions |
| `RELEASE_CHECKLIST.template.md` | General release readiness and verification |
| `MOBILE_RELEASE_CHECKLIST.template.md` | App store, signing, privacy, testing, and staged rollout |
| `PRIVACY_DATA_INVENTORY.template.md` | Data collected, purpose, recipients, retention, controls |
| `DATA_CARD.template.md` | Dataset provenance, quality, limits, and governance |
| `MODEL_CARD.template.md` | Model intended use, evaluation, limitations, and monitoring |
| `DECISION_LOG.template.md` | Compact list of material decisions |

Templates are prompts, not proof of compliance or security. Fill them with project-specific facts and remove sections that truly do not apply.
