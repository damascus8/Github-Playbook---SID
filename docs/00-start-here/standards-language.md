# How to read standards in this Playbook

To avoid ambiguity, this Playbook uses these words:

- **MUST:** baseline requirement for a repository that claims to follow the standard. A legitimate exception should be recorded.
- **SHOULD:** strongly recommended default. Skip it only when the trade-off is understood.
- **MAY:** optional technique that can be chosen based on project needs.
- **Required document:** expected unless the project owner records a reason it does not apply.
- **Free-first:** the default recommendation uses free functionality, but plan limits and third-party terms still apply.

The Playbook is deliberately risk-based. Requirements for a public library or a service that handles sensitive data will be stronger than those for a tiny personal script. The project owner is responsible for selecting and implementing the appropriate controls.
